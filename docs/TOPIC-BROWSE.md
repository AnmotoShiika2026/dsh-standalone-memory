# 按项目、人物或话题回看精选原话

可以问：「在这个工作区，帮我找找提到潮汐计划的记忆」「哪些原话提到顾澜？」「把说到蓝晒的那条展开」。这些是**关键词找候选，再展开证据**，不是生成一份人物档案或枚举全库。只读现有已保存条目，不需要开启对话归档、运行嵌入模型或重新索引聊天历史。

1. 用 `stm_search` 查一个具体词，例如 `{"query":"蓝晒","limit":5}`。一次至多列出五个候选。要从一个话题转到人物，可以从原文中选出姓名再搜。候选摘要可能经过编辑，不是原话；检索结果可能不全，尤其是同义词或同名者。
2. 用 `stm_read` 展开命中的 `id`，例如 `{"id":"<命中的 id>","limit":200}`。要读后文，沿 `nextOffset` 继续读，直到它为 `null`。核对 `text` 和 `source`，并区分 `sourceStatus`：`verified` 仅表示已和可访问的宿主用户消息逐字核对，不证明现实事实；`unavailable` 或 `mismatch` 不应叫作已核验原话。`superseded` 是曾经的说法，不当作当前值；存在争议不要仅按搜索顺序定结论。
3. 范围由当前 profile 与会话初始工作区的真实路径决定，无需也不能在参数里指定别的工作区。同名目录不互通。条目被忘记后，旧句柄不再能读；没有结果应说「此范围内没有找到匹配条目」，不能说「从来没提过」。

该入口没有可遍历的实体关系图、同名人物消歧或完整目录。测试以合成资料，直接调用已注册的工具处理函数及实际 SQLite 库；并非真实 GUI、模型选工具或所有自然语言问法的验收。
